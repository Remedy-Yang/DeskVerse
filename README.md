# DeskVerse · 分工三：GLB 三维场景工作台

可以导入 GLB，在网页中独立移动、旋转、缩放模型。已包含本地 Three.js r180、解码器和简体中文 OCR 资源，不依赖外部 CDN。基础摆放和尺寸图 OCR 无需 API Key；照片生成 GLB 另需本机 Python 代理、Rodin API 密钥及额度。

## 当前开发快照

- 已同步商品尺寸图本地 OCR、多规格尺寸选择、桌柜高校准与更远的椅子视角。
- 已替换新版材质桌柜，支持四个抽屉收纳、柜门铰链、独立椅子拖动与部件级碰撞提醒。碰撞不限制移动。源资产保留在 `deskmodels/桌子/agentic_0005_pack_glb_model_material_transferred.glb`，浏览器加载 `dist/assets/desk-real.glb`，旧 PBR / Shaded 文件保留作备份。
- 木质模型使用原始嵌入纹理，渲染材质会降低过强环境反光并保留木纹；左侧新增宿舍光照模拟，可切换白天、窗边侧光、夜晚、暖色台灯和模型展示，并独立调整亮度与冷暖。
- `deskmodels/` 收录杯子、桌子、键盘、鼠标四组原始资产，每组包含 PBR / Shaded 两个 GLB 和商品尺寸图。该目录用于团队共享，不会自动加载全部模型。
- 照片生成 GLB 已接入主应用：选择照片、核对预览和名称、确认云端上传及积分消耗后提交；任务状态独立显示，完成后下载 GLB 并自动放入场景。
- 照片模型导入时根据物品名称和模型外形估算朝向，并套用类别参考尺寸；提供杯瓶、鼠标、键盘、显示器、手机、音箱等类别的三组参考值。不是图像语义识别或照片测量，无法保证未知物件的类别、正反面或真实尺寸正确。
- 基础摆放和尺寸图 OCR 仍可通过静态 HTTP 服务离线使用。照片建模必须通过 `start.py` 启动，需要联网访问 Rodin，会上传所选照片并产生账户费用。
- `.env.example` 仅提供空配置项；真实密钥只放在被 Git 忽略的 `.env` 或环境变量 `RODIN_API_KEY`，不得提交。生成任务和下载模型放在被 Git 忽略的 `.deskverse/`。
- 本次集成负责人：Codex；范围为照片建模入口、Rodin 任务提交/查询/下载和场景导入。验收要求为端到端模拟任务通过、重复提交不创建第二个付费任务、凭据不出现在响应或 Git 中。真实付费生成由用户确认后发起。

## 立即使用

在线页面：https://deskverse-studio-aee02.rocky-fly-2036.chatgpt.site

1. 点击右上角「导入 GLB」，或把一个/多个 `.glb` 文件拖入网页。
2. 点击模型或左侧资产列表选中物品。
3. 选中模型后默认显示 X/Y/Z 三轴箭头，拖动箭头即可在空间中自由移动。按住鼠标中键拖动环绕观察；Shift＋中键拖动平移视角。
4. 选择「旋转」后拖动彩色圆环，可绕 X/Y/Z 轴旋转；右侧也能精确输入角度。
5. 导入时会自动缩放到可观察的大小。请在右侧输入实际宽、高、深，再点击确认尺寸。
6. 导入真实桌子时用左侧「导入真实桌子 GLB」，辅助桌面会隐藏。

初始示例台灯仍是程序化 GLB；当前包另内置用户提供的桌子和显示器 GLB，并按图片标注设置初始尺寸。新版桌子中的 16 个椅子部件被提取为独立可选对象，无需额外导入。

## 在自己的电脑运行

解压整个源码包，保留目录结构。需要 Python 3，浏览器推荐 Chrome 或 Edge 并启用硬件加速。

Windows：双击 `启动_Windows.bat`，或者在源码目录运行：

```powershell
py start.py
```

macOS / Linux：

```bash
python3 start.py
```

随后打开 http://127.0.0.1:8000 。在终端按 Ctrl+C 停止。`start.py` 只绑定本机，不对局域网开放。

端口被占用时可用 `python3 start.py --port 8002`；自动化验收可加 `--no-browser`。`npm start` 同样启动这个本机代理。

## 照片生成 GLB

首次配置密钥时运行以下命令，输入不会回显；本机 `.env` 以仅当前用户可读写的权限保存，且已被 Git 忽略。

```bash
python3 scripts/configure-rodin.py
python3 start.py --port 8002
```

1. 点击左侧「照片生成 GLB」，选择 PNG / JPG / WebP 单物品照片（不超过 20 MB）。
2. 核对照片和物品名称，勾选云端上传与积分消耗确认，再点击「确认并生成」。当前固定使用 Rodin Regular / PBR / GLB，不自动启用额外付费选项。
3. 任务列表显示提交、排队、建模和下载状态。生成期间可以继续编辑场景，也可关闭窗口；刷新后会恢复本机任务记录。
4. 当前标签页提交的模型完成后自动放入场景。历史模型可点击「放入场景」或「下载 GLB」，不会重新收费生成。
5. 照片生成不提供准确实物尺寸；生成后使用尺寸图 OCR / 商品规格或尺寸输入校准。

网络超时或服务重启时，不会自动重新提交付费任务；提交状态不明的任务应先在 Rodin 控制台核对。同一照片的进行中/已完成任务会复用，重试下载不会重新建模。任务和模型保存在 `.deskverse/`，API Key 和任务订阅信息不会返回浏览器。本机代理不是可直接公网部署的多用户服务。

可运行 `python3 scripts/check-rodin.py` 只读验证密钥及当前余额，该命令不会上传照片或创建生成任务。账户可用不代表每次任务一定成功，额度、权限、网络和图片内容仍可能影响生成。

也可以用任意静态 HTTP 服务托管 `dist/`。**不要直接双击 index.html**，ES 模块与解码器需要 HTTP。

直接运行不需要 npm。修改依赖或运行开发测试时需要 Node.js：

```bash
npm ci
npm test
npm run test:server
node scripts/check-static.mjs
```

`node scripts/vendor.mjs` 与 `node scripts/vendor-ocr.mjs` 会重新整理本地浏览器依赖；`node scripts/demo-assets.mjs` 重新生成示例 GLB。

## 抽屉收纳

- 左侧下拉框选择「左侧抽屉」或「右侧下 / 中 / 上层抽屉」，再拉开 / 收回或拖动滑杆；也可单击场景中的抽屉部件开合。左抽屉沿 +Z、右抽屉沿 -X 平移，不缩放或拉长部件。
- 点击抽屉标题旁的聚焦图标查看内腔。拉开至少 50% 后，选中物品，点击「收纳选中物品」；也可用「点击落点」点抽屉底板，按落点收纳。
- 收纳优先寻找内腔内的空位；空间不足时仍允许放入并提醒，不改变尺寸。当前左侧内腔约宽 55.6 × 高 6.5 × 深 30.1 cm，来自模型而非商家实测；24 cm 高杯子超出该浅抽屉，但不会因此锁住用户操作。
- 已收纳物品随所属抽屉移动；「取回桌面」直接回到 Y=0，重叠时提示但不拒绝。拖动物品使底部中心移出内腔后解除跟随。开合、收纳、椅子移动和柜门转动均可撤销 / 重做。
- 右侧原资产只有面板，因此新增可见的底板、后板和侧板，并按柜体间隙估算内腔；UI 标注「估算内尺寸」，导出 `estimated:true`。这不是商家的抽屉实测尺寸，精确收纳需实际校准。
- 「拉出椅子」沿 +Z 移动 35 cm 并进入拖动模式；椅子默认贴地 Y=-76。柜门使用实际铰链转动，最大约 130 度；门板已延伸到左柜开口边界，关闭时覆盖完整。关闭柜门会自动收回所有打开抽屉并提示；在柜门关闭状态拉抽屉会自动开门。柜门、椅子和抽屉相交时显示红色外框和提醒，但仍能完整开合、自由移动。
- 原模型存在面板与柜框、后横撑、床梁相交的连接处，运行时为这些运动部件留出间隙；原始 GLB 和尺寸图均不改写。渲染使用对数深度、合理近裁剪面，重新校准几何后清除旧切线，并关闭显示器自阴影以减轻闪烁。
- 光照预设只改变场景灯光、背景、地面显示和曝光，不修改 GLB 贴图文件。`模型展示`使用深色背景与轮廓光，接近产品展示图；`宿舍白天`是默认工作场景。
- 原商品尺寸图文件不变。新版模型包括椅子、床架和多个独立部件，因此通过命名桌板锚点校准：总高 180 cm、桌板高 76 cm、桌面 137 × 55 cm、整体深度 85 cm；保持桌板 Y=0，不能把新增床架的最高点直接当作桌面。

新增的体验交互：

- 选中物品后点击底部「点击落点」；移动鼠标查看蓝色终点标记和 XYZ 坐标，再用左键单击放置。此模式左键不会旋转视角；中键环绕、右键平移、滚轮缩放。
- 桌子是固定资产：始终保持 `X=0、Z=0`，桌面顶面固定为 `Y=0`；画布点击不会选中或移动桌子，右侧位置、旋转、尺寸和删除操作也会锁定。
- 进入「点击落点」后，鼠标悬停在桌子或架子的水平表面上会显示实时 `X / Y / Z` 坐标；点击侧面等非水平表面会被拒绝，避免物品悬浮。
- 右侧尺寸区同时显示「导入尺寸」和「当前尺寸」；可使用缩放手柄、数字输入，或选择小 / 标准 / 大三档等比尺寸。
- 单个物品可上传商品尺寸图；浏览器本地 OCR 会提取商品尺寸候选并立即生成可选规格，也可编辑名称与宽 X / 高 Y / 深 Z 后应用。OCR 可能混淆商品本体与包装尺寸，应用前应核对；图片不会上传服务器。识别失败时仍可手动添加规格。
- 画布右上角工具从左到右是「初始视角」「近距离俯视」「聚焦选中物品」「网格开关」，图标下方现在直接显示文字，悬停也有完整说明。
- 画布右上角「观察距离」支持 50–600 cm 滑杆。
- 画布右上角「坐在椅子上」是相机预览：坐高按 `0.25 × 身高 + 2 cm` 初估，可微调；它不是人体测量值。前后距离 25–500 cm、7 个预设，视角以实体椅子中心对齐。按钮进入后变为「退出坐姿视角」，再次点击或按 Esc 即可退出；调整相机不会移动实体椅子。
- 左侧「椅子前后位置」滑杆控制实体椅子相对导入原位的前后偏移：`-30 cm` 到 `+120 cm`，正数向外拉，负数向桌子方向推；「拉出椅子」按钮会直接设置为 `+35 cm`。
- 当前包已内置 `base_basic_pbr.glb` 桌柜和 `monitor_demo.glb` 显示器，首次打开会自动载入；桌柜按尺寸图校准为总高 `180 cm`，桌板高 `76 cm`、桌面 `137 × 55 cm`，并把桌板设为 `Y=0` 工作面。显示器初始尺寸为 `53.9 × 40.7 × 16.3 cm`。
- 椅子已从新版桌柜提取为独立对象，尺寸来自同一模型校准，不额外扩大或缩小。

输入框内的快捷键不触发三维操作。默认关闭「贴合桌面」，X/Y/Z 均可自由调整；可手动开启贴合。开启贴合后，拖动含 Y 的移动手柄或修改 Y 数值会自动解除贴合，避免高度被锁回桌面。滚轮滚动仍用于缩放。

## 资产约定与边界

- 通用 GLB 对应独立对象，不自动猜测拆分；内置新版桌柜例外，按命名部件提取椅子并分组抽屉和柜门。
- 支持内嵌几何、贴图的 glTF 2.0 GLB，已接入本地 Draco、Meshopt、KTX2 解码器。压缩格式的实际兼容性仍需具体资产验收。
- 不加载 GLB 引用的外部图片或 `.bin`，避免丢贴图与外部资源依赖；请在导出时嵌入资源。
- 单文件上限 80 MiB；一次会话累计载入上限 240 MiB。删除模型仍为撤销保留资源，刷新后释放。
- 每个模型初次导入会放到工作面，之后默认自由移动；不会持续锁定高度，也不会因为重叠而被自动挪走。普通 GLB 商品最大边默认 32 cm；照片模型按类别参考值初始化，无法判断类别时用通用 20 cm 最大边参考。普通桌子最大边默认 140 cm；内置桌柜按 180 cm 总高校准。
- 右侧「常见参考尺寸」提供类别和三个尺寸选项，所有参考值均标为未校准，不代表统计意义上的市场众数。支持「自动扶正」及 X / Z 轴 90 度翻转，方向和参考尺寸变更可以撤销。照片生成对话框可提前选类别，偏好按任务编号保存在本机浏览器，既有任务重新放入不需要再次生成或扣费。
- 尺寸图上传、OCR 多规格和手工规格仍单独保留；选择常见参考不会覆盖商家规格。商家规格由用户核对后选择使用，参考值不会伪装成实测值。原始下载 GLB 不被改写，朝向修正保存在布局的 `modelOrientation` 中。
- 实际业务单位是厘米。模型尺寸是**旋转前的局部外形尺寸**，不等于旋转后的世界包围盒，也不等于显示器底座占地。
- 「贴合桌面」默认用当前工作面高度对齐；「点击落点」会额外射线命中真实桌子 GLB 的水平表面，因此可以落到不同高度的架子上。斜桌、复杂台阶、桌面上的装饰仍不提供精确碰撞判断。
- 动画 GLB 显示静态姿态；当前不播放骨骼动画。
- 碰撞按独立网格的定向包围盒（Three.js OBB）检查，显示侧栏状态、橙色选框和短暂提醒，不回退位置、不限制高度、不阻止旋转缩放。平移的连续 SAT 只用于提醒经过障碍的路径。普通自由移动与明确开启的贴面 / 吸附模式是两回事；用户主动开启贴面或吸附时仍按对应规则执行。
- 这是近似重叠提醒，不是三角面精确物理、重力、弹跳或软体模拟。复杂凹形、剪切和镜像模型可能产生保守提醒；装配用铰链和滑轨忽略内部连接。没有桌面越界限制或 PICO / VR。
- 模型在浏览器本机解析，不上传服务器；刷新会清空当前场景。导出布局只保存 JSON，不嵌入 GLB，也没有导入布局的 UI。请保留原始 GLB。

## 给 4 号同学的接口

入口 `dist/app.js`，纯数学与数据处理 `dist/core.js`。共享的场景状态来自同一组 Three.js 对象，没有另一套位置数据。

```js
// 读当前完整布局（对象副本，不要直接修改返回值来移动场景）
const state = window.deskverse.getState();

// 选中某个物品
const movable = state.objects.find(object => !object.locked);
window.deskverse.select(movable.id);

// 修改位置和旋转，经过统一更新后同步界面、贴桌面和事件
const result = window.deskverse.setTransform(movable.id, {
  position: [20, 0, -10], // X/Y/Z，厘米
  rotation: [0, 45, 0], // X/Y/Z，角度，Euler XYZ
  grounded: true
});

// 用户拖动、修改数值、导入、删除、撤销时，读取同一数据源
window.addEventListener('deskverse:change', (event) => {
  const { objects, surface } = event.detail;
  // 接入越界 / 重叠判断。这里只提供数据，不把 AABB 当作精确占地。
});
```

`getState()` 顶层包含 `schemaVersion`、`units`、`coordinateSystem`、`surface`、`lighting`、`objects`、`drawers`、`doors` 和 `collision`。向量统一为 `[X,Y,Z]` 数组，旋转单位为度。`objects` 每个条目包含：

| 字段 | 含义 |
| --- | --- |
| `id` / `name` / `sourceFile` | 当前会话唯一 ID、显示名、原始 GLB 文件名 |
| `role` | `item` 或 `table` |
| `position` | 归一化模型底部中心的世界坐标 |
| `rotation` / `rotationOrder` | 度数 / `XYZ` |
| `scale` | 相对原始 GLB 包围盒的模型缩放，已包含导入归一化比例 |
| `dimensionsCm` | 旋转前外形宽 X、高 Y、深 Z，不能直接当作底座尺寸 |
| `worldBoundsCm` | 旋转后世界轴对齐包围盒，`min` / `max` 均为 XYZ 数组 |
| `grounded` / `calibrated` / `locked` / `demo` | 是否贴桌面、用户是否确认尺寸、是否固定资产、是否内置示例 |
| `storage` | 未收纳时为 `null`，收纳后为 `{drawerId}`；位置和 `worldBoundsCm` 始终仍是世界坐标，不是抽屉局部坐标 |
| `modelOrientation` | 导入资产在归一化前的朝向修正四元数 `[x,y,z,w]`，无修正包装时为 `null`；独立于用户的 `rotation` |
| `referenceSize` | `{category,index,estimated:true}` 或 `null`；是参考值标记，不是实物校准结果 |

`drawers` 无可用抽屉时为空数组；每项包含 `id`、`name`、`opening`（0–1）、`travelCm`、`interiorCm: {min,max}`（世界坐标内腔）和 `dimensionsCm`（XYZ 内腔尺寸）。抽屉移动时通过原有 `deskverse:change` 发出更新；消费者可以忽略这些新增字段，原 `objects` 字段语义不变。

右侧抽屉额外包含 `direction:[-1,0,0]` 和 `estimated:true`，左抽屉沿 +Z。`doors` 包含 `id`、`opening`、`angleDegrees`。`collision.mode` 固定为 `warn`；`detected` 表示当前重叠、地面 / 内腔超出或最近路径提醒，`kind` 区分 `overlap` / `floor` / `capacity` / `path`，`message`、`objectId`、`part` 给出提醒信息。兼容字段 `blocked` 固定为 `false`。`setTransform` 对合法输入返回 `{accepted:true,collision}`，即使碰撞也保留目标变换；非法输入和固定资产仍按原接口报错。

`lighting` 包含 `preset`（`dorm-day`、`window-side`、`dorm-night`、`desk-lamp`、`studio`）、`intensity`（0.5–1.5）和 `warmth`（-100–100）。它只描述浏览器展示环境，不会改变物品尺寸或导出的 GLB。

初始参考桌面中心为 `(0,0,0)`，X 左右、Y 向上、Z 前后。默认参考桌面范围 X ∈ [-70,70]、Z ∈ [-37.5,37.5]。当前真实桌面固定在 `X=0、Z=0`，其顶面为 `Y=0`；`surface.heightCm` 仍表示当前水平摆放高度，架子水平表面可有不同的 Y 坐标。

当 `surface.type` 为 `model-work-surface` 时，`surface.heightCm` 指模型定义的实际桌板工作面，不一定是整件桌柜包围盒的最高点。尺寸图与商品规格只在当前浏览器会话中保留；规格尺寸由用户确认录入，避免误用包装尺寸。

吸附规则：三轴移动每 1 cm、旋转每 15°、缩放每 0.05 比例。直接拖动只吸附 X/Z。尺寸校准发生变化或手柄缩放后，已校准标记会清除，需要重新确认。

`scripts/check-furniture-ui.mjs` 检查椅子拖动、四抽屉、柜门、重叠只提醒、右侧收纳、自由坐标输入和静止画面像素稳定性，截图位于 `.deskverse/qa/furniture/`。静止截图只验证当前 Chrome 环境，不保证所有显卡上的渲染表现。

建议你们的第一轮真实验收：

1. Windows Chrome / Edge 打开页面，确认示例有正常外形、材质，控制台无红色报错。
2. 导入当前罐子 GLB，确认外形与贴图正常；从正面、背面、顶面查看并恢复视角。
3. 输入一个已知实物尺寸，确认等比例缩放符合预期。
4. 同时导入两个独立物品，分别移动和旋转，确认另一个不跟随。
5. 默认直接沿 Y 轴移动；开启贴合后底部回到工作面，再拖动 Y 箭头应自动解除贴合。
6. 按住中键拖动确认相机环绕；Shift＋中键应平移，滚轮应缩放，模型位置不变。
7. 导入桌子，校准尺寸，确认商品贴合到它的包围盒顶面。
8. 撤销移动/旋转/删除，导出 JSON，并与屏幕上输入值对照。
